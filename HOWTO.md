# HOWTO — как пройти по всему приложению

Этот документ — пошаговый гид по учебному SPA-демо «Vue 3 + transformers.js».
Пройдите все 6 этапов — увидите каждую фишку приложения в действии,
от анимаций до инференса нейросетей в браузере.

Предполагается, что приложение уже установлено и запущено:

```bash
npm install
npm run setup   # скачать модели (384 МБ, один раз)
npm run dev     # http://localhost:5173
```

## Этап 1. Хаб-страница — вступление и анимации

**URL:** http://localhost:5173/

**Что смотреть:**

1. **Staggering-появление карточек**. После загрузки страницы карточки
   «Детектор объектов» и «Переводчик» появляются не одновременно, а по одной
   с задержкой 120ms. Это `<TransitionGroup>` с CSS-переменной `--i`:
   `transition-delay: calc(var(--i) * 120ms)`.

2. **Прогресс-бар изучения**. Серая полоса под заголовком. Сейчас она
   пустая — вы ещё ничего не изучили. По мере прохождения этапов 3 и 5
   полоса будет заполняться.

3. **Расширенный список технологий**. Внизу страницы — список Vue-технологий
   с разбивкой по категориям: «Ядро Vue 3», «Реактивность», «Анимации»,
   «Композаблы и шаблоны». Каждая технология — с описанием, где используется.

4. **Сайдбар**. Слева — навигация. Внизу — краткий список технологий
   мелким шрифтом: «Composition API · Router · Pinia · Transition».

**Vue-техники, которые видите:**
- `<TransitionGroup>` со staggering через CSS-переменную
- `useProgressStore` с геттером `percent` для прогресс-бара
- `techStackFull` из единого справочника `src/data/techStack.js`

## Этап 2. Детектор — демо

**URL:** http://localhost:5173/detector

**Что делать:**

1. **Дождитесь загрузки модели**. Под заголовком — индикатор статуса
   с пульсирующей точкой и прогресс-баром. Модель `Xenova/detr-resnet-50`
   весит 166 МБ, первый раз грузится 10–30 секунд (потом из кэша браузера —
   мгновенно). Статус должен стать «Модель готова».

2. **Нажмите «Пример: кот»**. Откроется изображение, над ним кратко
   мелькнёт «Идёт детекция…», затем на canvas появятся цветные боксы
   с подписями классов и confidence. Под изображением — список найденных
   объектов, элементы появляются по одному с задержкой 90ms
   (`<TransitionGroup>` со staggering).

3. **Попробуйте drag&drop**. Перетащите любую картинку с компьютера в
   зону загрузки. То же самое — спиннер «Идёт загрузка…» → картинка →
   «Идёт детекция…» → боксы.

4. **Загрузите большое фото** (можно свое). Изображение ограничено
   512px по высоте — пропорции сохраняются, canvas-overlay автоматически
   подстраивается.

5. **Посмотрите сайдбар**. В блоке «Активная модель» должно быть
   `Xenova/detr-resnet-50`.

**Vue-техники, которые видите:**
- `usePipeline` с `dtype: 'fp32'` — обёртка над transformers.js
- `<Transition>` для появления canvas, прогресс-бара, «Идёт детекция…»
- `<TransitionGroup>` со staggering для списка объектов
- `watch` на `imageUrl` + `instance` — авто-запуск детекции
- `computed` для форматирования confidence в проценты
- `template ref` на `<canvas>` — рисование боксов поверх `<img>`
- `inject('detectedClasses')` — список найденных классов передаётся
  в сайдбар и во вкладку «Как это работает» (понадобится на этапе 3)
- `max-height: 512px + object-fit: contain` — ограничение размера картинки

## Этап 3. Детектор — вкладка «Как это работает»

**URL:** http://localhost:5173/detector?tab=how

**Что делать:**

1. **Переключите вкладку**. Над контентом — две кнопки: «Демо» и
   «Как это работает». Нажмите вторую. URL автоматически обновится
   с `?tab=how`. Можно обновить страницу — вкладка сохранится.

2. **Прокрутите 7 секций**:
   - **Модель** — описание архитектуры DETR + ResNet-50
   - **Классы COCO** — сетка из 80 чипсов с поиском
   - **Ограничения** — почему арбуз → «bird», хамелеон не определится
   - **Что распознаётся хорошо** — галерея из 3 примеров
   - **Что распознаётся плохо** — галерея из 3 проблемных примеров
     (арбуз, хамелеон, дерево с плодами)
   - **Что попробовать** — список экспериментов
   - **Викторина** — 3 вопроса

3. **Поищите классы**. В блоке «Классы COCO» введите в поле поиска,
   например, «cat» или «банан». Сетка фильтруется в реальном времени
   через `computed`. Анимация фильтрации — `<TransitionGroup>` с `list-move`.

4. **Вернитесь на вкладку «Демо» и загрузите кота**. Переключитесь
   обратно на «Как это работает» — чипс «cat» в списке COCO подсветится
   зелёным с галочкой «✓». Это работает через `inject('detectedClasses')`:
   список найденных классов реактивно обновляется из DetectorPanel.

5. **Кликните карточку в галерее** «Что распознаётся плохо» — например,
   хамелеона. Вкладка автоматически переключится на «Демо», появится
   спиннер «Идёт загрузка…», потом картинка, потом «Идёт детекция…».
   Скорее всего, детектор ничего не найдёт — это и есть демонстрация
   ограничения модели.

6. **Пройдите викторину**. Ответьте на 3 вопроса, нажмите «Проверить».
   Правильные ответы подсветятся зелёным, неправильные — красным.
   Для каждого вопроса появится объяснение. Если все 3 верно —
   увидите «всё верно! 🎉».

**Vue-техники, которые видите:**
- `useRoute` + `useRouter` — переключение вкладок через `?tab=how`
- `defineAsyncComponent` — вкладка грузится лениво
- `<KeepAlive>` — состояние демо сохраняется между переключениями
- `<Transition mode="out-in">` — плавная смена вкладок
- `<component :is>` по типу секции — рендеринг 6 разных секций
- `provide/inject` — связь галереи с демо-вкладкой
- `watch` на `inject`-значении — реакция на выбор примера
- `nextTick + requestAnimationFrame` — даём браузеру покрасить
  спиннер ДО блокирующего WASM-инференса
- `v-model` на radio — викторина
- `computed` для `allCorrect` / `correctCount` / `canSubmit`
- Динамические классы — подсветка правильных/неправильных ответов
- `useProgressStore` — отмечает посещение и прохождение викторины
- Персистенция в `localStorage` — прогресс сохраняется между сессиями

## Этап 4. Переводчик — демо

**URL:** http://localhost:5173/translator

**Что делать:**

1. **Дождитесь загрузки моделей**. Тут грузятся две модели параллельно
   (`Xenova/opus-mt-ru-en` и `Xenova/opus-mt-en-ru`, по 108 МБ каждая).
   Индикатор покажет «Модель готова» только когда ОБЕ загрузились —
   это важно, иначе был баг с рассинхроном сайдбара и индикатора.

2. **Введите русский текст**. Например:
   ```
   Маша мыла раму. Дождь идёт. Завтра будет солнечно.
   ```
   Автоопределение направления увидит кириллицу → поставит «RU → EN (авто)».

3. **Нажмите «Перевести»**. Текст разобьётся на 3 предложения, каждое
   переведётся отдельно. Результаты появляются по одному с задержкой
   80ms (`<TransitionGroup>` со staggering) — эффект инкрементального
   стриминга. Под полем ввода — счётчик символов «35 / 500».

4. **Нажмите кнопку ⇄ (Swap)**. Направление переключится на «EN → RU (вручную)»,
   старый перевод очистится, и вы сможете ввести английский текст.
   Кнопка Swap поворачивается на 180° при наведении — CSS-анимация.

5. **Вернитесь на хаб и снова зайдите в переводчик**. Модели загрузятся
   мгновенно из кэша браузера (`env.useBrowserCache = true`).

**Vue-техники, которые видите:**
- Два `usePipeline` — по одному на направление
- `Promise.all` в `onMounted` — параллельная загрузка обеих моделей
- `computed` для `effectiveDirection` — автоопределение по кириллице
- `watch` на `inputText` — сброс результатов при очистке
- `watch` на `pendingText` — реакция на выбор примера
- `<TransitionGroup>` со staggering для предложений перевода
- Счётчик символов с динамическими классами `.warn` / `.over`

## Этап 5. Переводчик — вкладка «Как это работает»

**URL:** http://localhost:5173/translator?tab=how

**Что делать:**

1. **Переключите вкладку** «Как это работает».

2. **Прокрутите 6 секций**:
   - **Модель** — описание MarianMT (encoder-decoder Transformer)
   - **Что переводится хорошо** — 3 примера: лирический, ироничный, пейзажный
   - **Что переводится плохо** — 2 примера: диалог, философский
   - **Технические особенности** — почему «корневой компонент» может
     перевестись как «root component»
   - **Что попробовать** — список экспериментов
   - **Викторина** — 3 вопроса

3. **Кликните карточку в галерее примеров** — например, «лирический».
   Вкладка переключится на «Демо», текст автоматически подставится в
   поле «Исходный текст», старый перевод очистится, новый перевод
   запустится автоматически (нажимать «Перевести» не нужно).

4. **Кликните «диалог»** в секции «Что переводится плохо». Посмотрите,
   как модель справляется с разговорным стилем — перевод будет
   деревянным, буквально пословным.

5. **Пройдите викторину**. 3 вопроса про MarianMT, дословный перевод
   и разбиение на предложения. Если все 3 верны — прогресс изучения
   переводчика отметится как пройденный.

**Vue-техники, которые видите:**
- Те же, что в этапе 3, плюс:
- `watch(pendingText)` с `nextTick + translate()` — автозапуск перевода
- Сброс `manualOverride` при выборе примера — автоопределение снова работает
- `ExamplesSection` с CSS-классами по типу метки (`mark-лирический`,
  `mark-диалог` и т.д.)

## Этап 6. Хаб — финал и прогресс

**URL:** http://localhost:5173/

**Что делать:**

1. **Вернитесь на хаб**. Если вы прошли этапы 3 и 5 (посетили
   «Как это работает» на обеих страницах и прошли обе викторины),
   прогресс-бар должен быть заполнен на 100%, а рядом — надпись
   «всё пройдено! 🎉».

2. **Посмотрите сайдбар**. У ссылок «Детектор» и «Переводчик» должны
   быть зелёные галочки «✓» — признак изучения. Появились они через
   `<Transition>` — плавное fade-in.

3. **Нажмите «Сбросить прогресс»**. Появится confirm-диалог. Согласитесь —
   прогресс обнулится, галочки пропадут, прогресс-бар опустеет. Кнопка
   «Сбросить прогресс» сама исчезнет через `<Transition>` (она видна
   только если `progress.visitedCount > 0`).

4. **Обновите страницу**. Прогресс сохраняется в `localStorage` —
   после обновления всё на месте. Если вы сбросили прогресс на шаге 3 —
   после обновления он останется сброшенным.

5. **Откройте вкладку в режиме инкогнито**. Прогресс будет пустой —
   localStorage у инкогнито чистый.

**Vue-техники, которые видите:**
- `useProgressStore` с геттерами `percent`, `visitedCount`, `isComplete`
- `<Transition>` для условного появления кнопки «Сбросить прогресс»
- Персистенция в `localStorage` — `load()` при инициализации state,
  `persist()` после каждого действия
- `confirm()` — нативный браузерный диалог подтверждения

## Что попробовать ещё (бонус)

### 1. Откройте DevTools → Console

Видите подробные логи загрузки моделей:
```
[usePipeline:Xenova/detr-resnet-50] onnx/model.onnx 45.2%
[usePipeline:Xenova/detr-resnet-50] ✓ onnx/model.onnx
[usePipeline:Xenova/detr-resnet-50] Модель готова
```

### 2. Откройте DevTools → Application → Local Storage

Ключ `vue-transformers-progress` — JSON с состоянием прогресса:
```json
{ "visited": ["detector", "translator"], "quizPassed": ["detector"] }
```

### 3. Откройте DevTools → Network

При первой загрузке страницы видно, как качаются модели из `/models/`
chunk-ами (HTTP 206 Partial Content). При повторной — запросы идут в
`IndexedDB` (Cache API), сеть не дёргается.

### 4. Отредактируйте URL вручную

- `/detector?tab=how` — сразу на вкладке «Как это работает» детектора
- `/detector?tab=invalid` — fallback на «Демо» (неизвестный tab)
- `/detector?tab=` — fallback на «Демо» (пустой tab)

### 5. Проверьте, что KeepAlive работает

1. Зайдите на `/detector`, загрузите картинку, дождитесь боксов
2. Переключитесь на «Как это работает»
3. Вернитесь на «Демо» — картинка и боксы на месте, модель НЕ перезагружается

Если бы `KeepAlive` не было — при каждом переключении модель грузилась бы
заново (10+ секунд).

### 6. Проверьте provide/inject

1. Откройте `/detector`, загрузите кота
2. Перейдите на «Как это работает»
3. В поиске COCO введите «cat» — чипс «cat» будет с зелёной галочкой
4. Вернитесь на «Демо», загрузите собаку
5. Перейдите на «Как это работает» — теперь галочка на «cat» пропала,
   появилась на «dog». Это работает через `watch(detections)` в
   DetectorPanel, который обновляет `detectedClasses` (provide),
   и ChipsSection читает его через `inject`.
